# Обновление Life Tracker

Эта папка — отдельная копия проекта, не устанавливайте её поверх единственной копии данных. Исходный архив, системный npm-кэш и ваши старые сборки не изменены. Перед первым запуском новой версии экспортируйте JSON в старой версии: «Ещё → Данные → Экспорт». Electron и браузер имеют раздельные хранилища. Из-за изменения имени сборки возможно открытие нового профиля: если данных нет, используйте импорт. Не импортируйте поверх непроверенных новых данных — импорт заменяет содержимое.

## Что изменено

- Восстановлены scripts и devDependencies из сведений lock-файла; параметры Windows-выпуска — из `nsis-debug.log` исходного архива. `vite.config.ts` создаёт `web-dist`, `electron-builder` пишет в `release`. Electron, локальный запуск через `START.vbs` и оба способа публикации направлены на `web-dist`.
- В `app.asar` входят `web-dist`, `electron`, `package.json`. Исходники, тесты, старые сборки, кэш и карты исходников не включаются. Dexie встроен Vite в веб-код, поэтому находится в devDependencies; Electron импортирует только встроенные модули и сам Electron. Иконка `build/icon.ico` нужна для упаковки, но не для работы приложения.
- «Ещё → Учёба и задолженности»: предметы, работы, долги, точные и примерные сроки, а также обзор «По неделям» по всем предметам. Работу можно добавить в план на сегодня.
- «Ещё → Настройки → Текущий семестр»: укажите номер и дату начала. У предмета тоже должен быть тот же номер семестра. Неделя — семь дней от даты начала, независимо от дня недели; 7-я и 14-я отмечены как контрольные. Работа только с номером недели отображается в календаре в течение этой недели приблизительно, а указанная конкретная дата имеет приоритет. Предметы без совпадающего номера не привязываются к текущему началу семестра автоматически.
- «Календарь» объединяет дела, повторы, учёбу и тренировки. Фильтры «Всё», «Учёба», «Тренировки», «Дела» меняют отображение; недели и контрольные сроки в календаре показываются только в режиме «Учёба». Работа со сроком может быть добавлена в план выбранного дня. На экране «Сегодня» показываются ближайшие и просроченные учебные работы.
- Светлая и тёмная темы переключаются сверху, кнопка показывает текущую тему. Неровная волна идёт от стороны кнопки через экран около пяти секунд; при настройке уменьшения движения анимация отключается. По умолчанию светлая тема, системную можно включить в настройках. Сохранённый ранее выбор не перезаписывается.
- Карточка тренировки на «Сегодня» видна, когда на этот день в календаре есть задача категории «Тренировка» или записана активная/завершённая тренировка; автоматическое предположение графика зала само по себе её не показывает.
- Файл `AI_IMPORT_GUIDE.md` описывает передачу данных через полный экспорт и ручной импорт. Доступ к папке проекта сам по себе не даёт доступа к IndexedDB и не импортирует записи автоматически.
- Хранилище: жёсткий общий предел 300 МиБ пока не установлен. При доступной оценке браузера показывается предупреждение при достижении 240 МиБ, импорт файлов более 300 МиБ блокируется. Оценка приблизительная и может быть недоступна; данные автоматически не удаляются.

## Сборка в Windows

Распакуйте исходники в новую папку с ASCII-путём, например `C:\lt-build-new`; кириллица в пути может мешать сборке NSIS. Установите поддерживаемый Node.js LTS. Ниже команды выполняйте по одной. `npm ci` пересоздаёт `node_modules` **в текущей папке**, не используйте её на единственной копии проекта.

1. Перейти в распакованную копию:

```powershell
Set-Location 'C:\lt-build-new'
```

2. Установить зависимости:

```powershell
npm.cmd ci
```

3. Проверить типы:

```powershell
npm.cmd run check
```

4. Запустить тесты:

```powershell
npm.cmd test
```

5. Собрать установщик и portable. Этот шаг заново создаёт `web-dist` и файлы в `release` текущей копии:

```powershell
npm.cmd run build:desktop
```

6. Размер упакованного приложения:

```powershell
Get-Item -LiteralPath '.\release\win-unpacked\resources\app.asar' | Select-Object FullName, @{Name='МиБ';Expression={[math]::Round($_.Length / 1MB, 2)}}
```

7. Верхние папки архива:

```powershell
npx.cmd asar list '.\release\win-unpacked\resources\app.asar' | ForEach-Object { ($_ -split '[\\/]')[1] } | Group-Object | Sort-Object Count -Descending | Select-Object -First 15 Count, Name
```

Проверьте, что нет `.npm-cache`, `release`, `tests`, `src`, `tools`. После этого запустите `release\win-unpacked\Life Tracker.exe`, проверьте данные, добавление и изменение задачи, повтор, учебную работу и обе темы. Установщик и portable находятся в `release`. Сборка в среде разработки проверена только до стадии `--win --dir`: готовый установщик и работу exe в Windows нужно проверить на вашем компьютере.

## Старые сборки

`dist` и `release` из исходного проекта, проектный `.npm-cache`, временный `C:\temp\asar-check` и логи могут содержать результаты прошлых запусков. Они не входили в новую копию. Не удаляйте их, пока не сохранили нужные установщики и не проверили приложение. Системный npm-кэш не является частью приложения. Происхождение прежнего проектного кэша без настроек и переменных вашей Windows-среды определить нельзя.
